# Video to Markdown 浏览器插件产品与技术设计规格

- 状态：已确认
- 日期：2026-07-12
- 目标版本：MVP 0.1.0
- 目标浏览器：Chrome 114 及以上
- 仓库建议名称：`video-to-markdown-extension`

## 1. 摘要

Video to Markdown 是一个本地优先的 Chrome 浏览器插件。用户在 YouTube 或哔哩哔哩观看带字幕的视频时，可以直接从浏览器侧边栏提取已有字幕，并生成中文 Markdown 文档。

插件提供两种处理模式：

1. 高保真模式：尽可能保留字幕的信息顺序、表达细节和论证过程，只做清洗、断句、自然段恢复，以及必要的英文到中文翻译。
2. AI 精炼模式：在保留重要事实、数字、人物、案例和论证关系的前提下，生成结构化中文笔记。

MVP 不建设产品账号、云端数据库或自有模型代理服务。用户配置自己的 OpenAI 兼容模型 API，原始字幕与生成内容不经过本产品自有服务器。

## 2. 产品目标

### 2.1 目标用户

- 经常使用 YouTube、哔哩哔哩学习课程、访谈、播客和技术内容的中文用户。
- 希望把视频内容沉淀到本地知识库的学生、研究人员、开发者和内容创作者。
- 可以自行准备 OpenAI 兼容模型 API Key 的个人用户。

### 2.2 核心价值

- 用户不需要复制视频链接或切换到独立网站。
- 用户可以在观看页面内完成字幕识别、处理、预览与导出。
- 英文视频可以直接生成中文文档。
- 同一份字幕既可以生成接近逐字稿的内容，也可以生成精炼笔记。
- 输出是通用 Markdown 文件，不绑定任何笔记平台。

### 2.3 MVP 成功标准

- 对有可访问字幕的 YouTube、哔哩哔哩视频，插件能够识别视频和字幕轨道。
- 30 分钟左右的视频能够稳定生成结构正确的中文 Markdown。
- 高保真模式不静默漏掉任何已接收的处理分块。
- AI 精炼模式能够形成可独立阅读、层次清晰的中文笔记。
- 用户无需创建产品账号，配置模型后即可完成核心流程。

## 3. 范围

### 3.1 MVP 包含

- Chrome Manifest V3 扩展。
- Chrome Side Panel 侧边栏交互。
- YouTube 字幕适配器。
- 哔哩哔哩字幕适配器。
- 已有字幕轨道识别与选择。
- 中文字幕的规则化清洗和排版。
- 英文字幕到中文的高保真翻译。
- AI 精炼与长字幕分层汇总。
- 可选视频时间戳。
- Markdown 预览、复制和本地下载。
- OpenAI 兼容协议配置：API Key、Base URL、模型名称。
- 模型连接测试、分块重试、任务取消和明确的错误提示。
- 中英文 README、隐私说明、贡献指南和自动化质量检查。

### 3.2 MVP 不包含

- 无字幕视频的音频下载或语音识别。
- 飞书、Notion、Obsidian 等第三方平台同步。
- 云端任务历史、产品账户、订阅付费或跨设备同步。
- Gemini、Claude 原生协议。
- Safari、Firefox 和移动端适配。
- 播放列表或多个视频的批量处理。
- 在关闭侧边栏后继续后台生成。
- 英文原文与中文译文的双语输出。

### 3.3 后续扩展方向

- 音频转写与无字幕视频支持。
- Gemini、Claude 等原生模型适配器。
- 飞书等知识平台同步。
- 本地任务历史和断点续传。
- Firefox、Edge、Safari 支持。
- 播放列表批量处理与模板化输出。

## 4. 用户流程

### 4.1 首次使用

1. 用户安装插件。
2. 用户打开设置，填写 API Key、Base URL 和模型名称。
3. 插件要求用户授权该 Base URL 的具体来源权限。
4. 用户点击“测试连接”。
5. 连接成功后，配置保存在 `chrome.storage.local`。

### 4.2 视频处理

1. 用户打开 YouTube 或哔哩哔哩视频页面。
2. 用户点击扩展图标，打开 Side Panel。
3. 插件识别当前视频、时长、平台和可用字幕轨道。
4. 用户选择字幕轨道、处理模式和是否保留时间戳。
5. 用户点击“开始生成”。
6. 插件展示字幕提取、清洗、分块、翻译或精炼的实时进度。
7. 完成后，用户预览、复制或下载 Markdown。

### 4.3 页面切换

- 当前任务进行时，如果活动标签页切换到另一个视频，Side Panel 显示确认提示。
- 用户可以继续当前任务，或取消当前任务并加载新视频。
- MVP 不自动把任务转移到新视频，也不静默取消任务。

## 5. 功能需求

### FR-1 平台识别

- 插件仅在受支持的 YouTube、哔哩哔哩视频页面启用完整功能。
- 对首页、搜索页、频道页、动态页等非视频页面显示“不支持当前页面”。
- 平台识别逻辑不得依赖页面显示语言。

### FR-2 视频元数据

- 读取平台、视频 ID、标题、作者、规范 URL 和时长。
- 缺少非必要字段时允许继续处理。
- 标题用于 Markdown 一级标题与默认文件名，必须移除文件系统非法字符。

### FR-3 字幕轨道

- 列出可访问的字幕语言、字幕名称和自动/人工字幕标识（平台提供时）。
- 默认优先选择中文轨道，其次英文轨道，最后选择首个可用轨道。
- 用户可以在多个字幕轨道之间手动选择。
- 没有可访问字幕时返回 `NO_SUBTITLE`，不得降级为音频下载。

### FR-4 字幕标准化

- 解码 HTML 实体与平台转义字符。
- 去除空字幕和完全重复字幕。
- 合并滚动字幕造成的前后重叠文本。
- 保留每条字幕的开始和结束时间。
- 根据标点、时间间隔和长度恢复自然段。
- 标准化阶段不主动删除语气词、事实或观点。

### FR-5 高保真模式

- 中文字幕不调用模型改写，只进行确定性的清洗与排版。
- 英文字幕按自然段分块翻译为中文。
- 每个输入段落携带稳定 ID，模型输出必须保留对应 ID。
- 插件校验输出段落覆盖率、唯一性和顺序。
- 校验失败时只重试失败分块。
- 最终 Markdown 只保留中文，不保留英文原文。

### FR-6 AI 精炼模式

- 字幕按模型上下文窗口和安全余量分块。
- 第一阶段从每块提取章节候选、观点、事实、数字、人物、案例和结论。
- 第二阶段合并各块结果，消除重复并恢复全局结构。
- 输出必须保留关键事实和论证关系，不得把未经字幕支持的内容写成事实。
- 对模型返回的结构执行校验；无法修复时保留可用结果并提示用户。

### FR-7 时间戳

- 用户可以开启或关闭时间戳。
- 时间戳链接使用平台支持的原视频定位格式。
- 高保真模式按自然段插入时间戳。
- AI 精炼模式仅在能追溯到来源字幕时插入时间戳，不伪造定位信息。

### FR-8 任务控制

- 显示当前阶段、完成分块数、总分块数、百分比和已用时间。
- 支持取消当前任务。
- 支持重试单个失败分块。
- 失败时保留已经成功的分块结果。
- 关闭 Side Panel 会中止当前任务，并明确提示该限制。

### FR-9 Markdown 输出

- 完成后在 Side Panel 内显示只读预览。
- 支持复制到系统剪贴板。
- 支持下载 UTF-8 编码的 `.md` 文件。
- 默认文件名格式为安全化后的视频标题。
- 模型输出只作为文本或经过验证的结构化数据处理，不执行 HTML。

### FR-10 模型配置

- 支持 API Key、Base URL 和模型名称。
- Base URL 默认只接受 HTTPS；开发构建可以允许 localhost。
- 提供连接测试、更新密钥和删除密钥功能。
- 模型适配层以 OpenAI 兼容协议为首个实现。

## 6. Markdown 规范

### 6.1 公共元信息

```md
# 视频标题

> 来源：YouTube / 哔哩哔哩
> 作者：作者名称
> 视频：原始视频 URL
> 处理模式：高保真 / AI 精炼
> 生成时间：ISO 8601 本地时间
```

缺少作者时省略作者行，不输出空占位符。

### 6.2 高保真模板

```md
## 根据内容生成或恢复的章节标题

[00:03:24](带定位参数的视频 URL)

中文正文自然段。
```

如果用户关闭时间戳，则删除时间戳行，不改变正文结构。

### 6.3 AI 精炼模板

```md
## 内容概览

## 核心观点

## 章节笔记

### 章节名称

## 重要案例与数据

## 结论与启发
```

不存在案例或数据时允许省略对应章节，不输出虚构内容。

## 7. 统一数据模型

```ts
type Platform = 'youtube' | 'bilibili'

type VideoMetadata = {
  platform: Platform
  videoId: string
  title: string
  author?: string
  canonicalUrl: string
  durationMs?: number
}

type SubtitleTrack = {
  id: string
  language: string
  label: string
  isAutoGenerated?: boolean
}

type SubtitleCue = {
  id: string
  startMs: number
  endMs: number
  text: string
}

type VideoDocument = {
  metadata: VideoMetadata
  track: SubtitleTrack
  cues: SubtitleCue[]
}
```

内部数据模型不暴露平台私有响应结构。平台私有字段只存在于对应适配器内部。

## 8. 技术架构

### 8.1 技术栈

- WXT：扩展构建、多入口管理、开发与打包。
- React：Side Panel 与设置界面。
- TypeScript strict：业务代码、消息契约和数据模型。
- pnpm：依赖管理。
- Vitest：单元测试与契约测试。
- Testing Library：React 组件测试。
- Playwright：扩展集成与端到端测试。
- ESLint、Prettier：静态检查与格式化。

### 8.2 扩展组件

```text
YouTube / Bilibili 页面
        ↓
平台 Content Script + SubtitleAdapter
        ↓ 统一 VideoDocument
Side Panel 任务编排器
        ↓ 消息请求
Service Worker
        ↓ OpenAI 兼容 API
模型响应
        ↓
Processor 校验与合并
        ↓
Markdown Renderer
        ↓
预览 / 复制 / 下载
```

### 8.3 模块职责

#### Content Script

- 识别当前平台和视频页面。
- 读取当前页面上下文可访问的视频元数据与字幕信息。
- 调用平台适配器并返回统一数据。
- 不接收、不读取、不记录 API Key。

#### Side Panel

- 展示视频与字幕状态。
- 收集处理选项。
- 编排当前任务、管理取消信号和展示进度。
- 保存当前会话中的成功分块和错误状态。
- 关闭时取消未完成任务。

#### Service Worker

- 读取模型配置。
- 验证消息来源和请求结构。
- 向用户授权的模型来源发送请求。
- 映射网络、鉴权、限速和服务端错误。
- 返回模型文本或结构化响应，不向 Content Script 返回密钥。

#### Processor

- 清洗、去重、段落恢复和分块。
- 执行高保真翻译或分层精炼。
- 校验模型响应的 ID、结构、顺序和覆盖率。
- 合并成功结果并产生可重试的失败描述。

#### Markdown Renderer

- 从经过验证的领域对象生成 Markdown。
- 转义或规范可能破坏 Markdown 结构的内容。
- 生成平台时间戳 URL 和安全文件名。

### 8.4 核心接口

```ts
interface SubtitleAdapter {
  supports(url: URL): boolean
  getVideoMetadata(): Promise<VideoMetadata>
  getSubtitleTracks(): Promise<SubtitleTrack[]>
  getCues(track: SubtitleTrack): Promise<SubtitleCue[]>
}

interface ModelProvider {
  testConnection(): Promise<void>
  complete(request: ModelRequest): Promise<ModelResponse>
}
```

所有跨扩展上下文消息使用可区分联合类型，并在接收端执行运行时校验。不得信任来自 Content Script 的任意 URL、方法名或请求头。

## 9. 长视频处理策略

### 9.1 分块

- 以自然段为最小单元，不在句子中间硬切。
- 根据模型配置的上下文窗口、提示词占用和输出安全余量计算最大输入量。
- 无法确定模型上下文窗口时使用保守默认值。
- 相邻精炼分块保留有限重叠，以维持跨边界语义。
- 高保真翻译依赖稳定段落 ID，不通过重叠制造重复正文。

### 9.2 并发与退避

- 默认使用保守的小并发，避免瞬时触发限速。
- 遇到 429 或可重试的 5xx 错误时采用带抖动的指数退避。
- 尊重服务端提供的 `Retry-After`。
- 鉴权失败、无效模型、无效请求等错误不自动重复重试。

### 9.3 响应校验

- 高保真模式校验 ID 集合、唯一性和顺序。
- 精炼模式校验必需字段、字段类型和最大长度。
- 缺少部分输出时标记具体分块，不把任务误报为完整成功。
- Markdown 渲染器只接收通过校验的领域对象。

## 10. 权限与安全

### 10.1 Manifest 权限

- `sidePanel`：显示 Side Panel。
- `storage`：保存本地配置和偏好。
- `downloads`：导出 Markdown。
- YouTube、哔哩哔哩的限定页面来源权限。
- 模型 API 使用可选来源权限；配置 Base URL 后请求具体来源授权。

不申请 Cookie、浏览历史、麦克风、摄像头或不必要的全站永久访问权限。

### 10.2 密钥处理

- API Key 只写入 `chrome.storage.local`，不写入同步存储。
- API Key 只由设置页和 Service Worker 访问。
- UI 默认遮挡密钥，不提供明文日志。
- 所有错误对象和日志在输出前执行凭证脱敏。
- 删除密钥后立即使模型功能不可用，直到重新配置。
- 文档明确说明浏览器本地存储不是硬件级安全存储，不承诺绝对安全。

### 10.3 内容安全

- 不使用 `eval` 或动态远程代码。
- 不把模型返回内容作为 HTML 注入页面。
- Content Script 消息视为不可信输入，必须进行类型与来源校验。
- Service Worker 只允许访问用户已授权的模型来源，拒绝由页面传入的任意目标 URL。
- 原始字幕和生成结果不发送到产品自有服务器。

## 11. 错误模型

```ts
type ErrorCode =
  | 'UNSUPPORTED_PAGE'
  | 'NO_SUBTITLE'
  | 'SUBTITLE_EXTRACTION_FAILED'
  | 'INVALID_MODEL_CONFIG'
  | 'MODEL_AUTH_FAILED'
  | 'MODEL_RATE_LIMITED'
  | 'MODEL_CONTEXT_EXCEEDED'
  | 'MODEL_RESPONSE_INVALID'
  | 'NETWORK_FAILED'
  | 'TASK_CANCELLED'
```

### 11.1 恢复规则

- `UNSUPPORTED_PAGE`：引导用户打开受支持的视频页面。
- `NO_SUBTITLE`：说明 MVP 只处理已有字幕的视频。
- `SUBTITLE_EXTRACTION_FAILED`：允许重试，并提示可能是平台页面发生变化。
- `INVALID_MODEL_CONFIG`：跳转到设置并保留非敏感表单内容。
- `MODEL_AUTH_FAILED`：停止自动重试，提示检查密钥和 Base URL。
- `MODEL_RATE_LIMITED`：展示等待状态，并允许取消。
- `MODEL_CONTEXT_EXCEEDED`：降低单块大小后只重试失败分块。
- `MODEL_RESPONSE_INVALID`：执行一次受控修复或重试，仍失败则保留其他结果。
- `NETWORK_FAILED`：提示网络状态并允许重试。
- `TASK_CANCELLED`：保留已完成分块到当前 Side Panel 会话。

错误文案必须描述发生了什么、哪些结果仍然可用，以及用户下一步可以做什么。

## 12. 界面状态

### 12.1 未配置

- 显示模型配置入口。
- 核心生成按钮禁用。
- 用户可以先查看已识别的视频和字幕信息。

### 12.2 准备

- 显示平台、字幕语言、视频时长和标题。
- 提供模式、字幕轨道和时间戳选项。
- 解释所选模式会如何处理内容。

### 12.3 处理中

- 显示阶段、分块进度、百分比和已用时间。
- 显示取消按钮。
- 已成功结果不因单块失败而丢失。

### 12.4 部分完成

- 明确标识失败分块数量。
- 提供“重试失败部分”。
- 在用户明确选择时允许导出部分结果，并在文档中标注不完整。

### 12.5 完成

- 显示文档标题、字数、时间戳数量和 Markdown 预览。
- 提供下载、复制和重新生成。

## 13. 性能与隐私要求

- 字幕清洗和分块不得阻塞 Side Panel 的交互反馈。
- 30 分钟字幕在常见开发设备上应能顺畅完成本地预处理。
- 模型调用期间持续显示可感知的进度，而不是无限加载状态。
- 不使用分析追踪 SDK 作为 MVP 的默认依赖。
- 不收集浏览历史、视频观看历史、字幕内容或模型凭证。
- 隐私说明必须列出发送给模型提供商的数据范围，并说明该行为受用户所选提供商条款约束。

## 14. 测试策略

### 14.1 单元测试

- 字幕实体解码与空白规范化。
- 完全重复与滚动字幕重叠去重。
- 自然段恢复。
- 高保真段落 ID 生成与覆盖率校验。
- 上下文预算与分块边界。
- 退避与错误映射。
- 时间戳 URL 和安全文件名。
- Markdown 模板渲染。

### 14.2 固定样本测试

- 保存脱敏、最小化的平台字幕响应与 DOM 样本。
- YouTube 和哔哩哔哩分别覆盖人工字幕、自动字幕、多语言字幕和无字幕状态。
- 固定样本不得包含登录凭证、Cookie 或非必要个人信息。

### 14.3 模型契约测试

- 使用本地 Mock 验证成功、鉴权失败、限速、超长输入、无效 JSON、缺失 ID 和重复 ID。
- 自动化测试不得依赖或消耗真实 API Key。

### 14.4 组件与集成测试

- 设置表单与连接测试状态。
- 模式、字幕轨道和时间戳切换。
- 进度、取消、部分失败与单块重试。
- Content Script、Side Panel 和 Service Worker 消息契约。

### 14.5 端到端与人工测试

- 构建并加载 Manifest V3 扩展。
- 在受控页面完成字幕读取到 Markdown 下载的完整流程。
- 发布前分别使用公开 YouTube、哔哩哔哩视频进行人工冒烟测试。
- 实时平台冒烟测试不作为稳定 CI 的唯一依据。

## 15. 验收标准

1. 插件可以开发者模式加载，Manifest 无错误。
2. 扩展图标可打开 Side Panel。
3. 支持的视频页能够读取元数据和至少一个可访问字幕轨道。
4. 无字幕或不支持页面显示正确、可理解的错误。
5. 中文字幕可在不调用模型改写的情况下生成高保真 Markdown。
6. 英文字幕可通过 OpenAI 兼容模型生成仅含中文的高保真 Markdown。
7. AI 精炼模式输出符合既定章节结构。
8. 30 分钟视频可以完成处理，且进度持续可见。
9. 单块失败不会删除其他成功结果。
10. 导出的 Markdown 为 UTF-8，标题、链接和段落结构正确。
11. API Key 不出现在 Content Script、日志、错误消息或导出文档中。
12. 类型检查、单元测试、组件测试和构建在 CI 中通过。

## 18. 已确认的关键决策

- 产品形态采用 Chrome 插件，而不是独立网页或桌面应用。
- MVP 仅处理 YouTube、哔哩哔哩已有字幕的视频。
- 英文内容最终只输出中文，不保留双语正文。
- 模型层首版只支持 OpenAI 兼容协议。
- 飞书 CLI 或其他知识平台联动不属于本期范围。
- UI 使用 Side Panel，不使用短生命周期 Popup 承载主流程。
- 工程采用 WXT、React、TypeScript 和 pnpm。
- MVP 关闭 Side Panel 后任务中止，不提供后台续跑。
- 项目以 GitHub 开源为目标，采用 MIT License。

## 19. 实施前置条件
