# Video to Markdown 浏览器插件产品与技术设计规格

- 状态：0.2.0 已实现，进入发布验收
- 日期：2026-07-12
- 基线版本：MVP 0.1.0
- 当前版本：0.2.0（Side Panel 2.0）
- 目标浏览器：Chrome 114 及以上
- 仓库建议名称：`video-to-markdown-extension`

## 1. 摘要

Video to Markdown 是一个本地优先的 Chrome 浏览器插件。用户在 YouTube 或哔哩哔哩观看带字幕的视频时，可以直接从浏览器侧边栏提取已有字幕，并生成中文或英文 Markdown 文档。

插件提供两种处理模式：

1. 高保真模式：尽可能保留字幕的信息顺序、表达细节和论证过程，只做清洗、断句、自然段恢复，以及必要的英文到中文翻译。
2. AI 精炼模式：在保留重要事实、数字、人物、案例和论证关系的前提下，生成用户指定语言的结构化笔记。

MVP 不建设产品账号、云端数据库或自有模型代理服务。用户配置自己的 OpenAI 兼容模型 API，原始字幕与生成内容不经过本产品自有服务器。

## 2. 产品目标

### 2.1 目标用户

- 经常使用 YouTube、哔哩哔哩学习课程、访谈、播客和技术内容的中文用户。
- 希望把视频内容沉淀到本地知识库的学生、研究人员、开发者和内容创作者。
- 可以自行准备 OpenAI 兼容模型 API Key 的个人用户。

### 2.2 核心价值

- 用户不需要复制视频链接或切换到独立网站。
- 用户可以在观看页面内完成字幕识别、处理、预览与导出。
- 英文视频可以直接生成中文文档。
- 同一份字幕既可以生成接近逐字稿的内容，也可以生成精炼笔记。
- 输出是通用 Markdown 文件，不绑定任何笔记平台。

### 2.3 MVP 成功标准

- 对有可访问字幕的 YouTube、哔哩哔哩视频，插件能够识别视频和字幕轨道。
- 30 分钟左右的视频能够稳定生成结构正确的中文 Markdown。
- 高保真模式不静默漏掉任何已接收的处理分块。
- AI 精炼模式能够形成可独立阅读、层次清晰的中文笔记。
- 用户无需创建产品账号，配置模型后即可完成核心流程。

## 3. 范围

### 3.1 MVP 包含

- Chrome Manifest V3 扩展。
- Chrome Side Panel 侧边栏交互。
- YouTube 字幕适配器。
- 哔哩哔哩字幕适配器。
- 已有字幕轨道识别与选择。
- 中文字幕的规则化清洗和排版。
- 英文字幕到中文的高保真翻译。
- AI 精炼与长字幕分层汇总。
- 可选视频时间戳。
- Markdown 预览、复制和本地下载。
- OpenAI 兼容协议配置：API Key、Base URL、模型名称。
- 模型连接测试、分块重试、任务取消和明确的错误提示。
- 中英文 README、隐私说明、贡献指南和自动化质量检查。

### 3.2 MVP 不包含

- 无字幕视频的音频下载或语音识别。
- 飞书、Notion、Obsidian 等第三方平台同步。
- 云端任务历史、产品账户、订阅付费或跨设备同步。
- Gemini、Claude 原生协议。
- Safari、Firefox 和移动端适配。
- 播放列表或多个视频的批量处理。
- 在关闭侧边栏后继续后台生成。
- 英文原文与中文译文的双语输出。

### 3.3 后续扩展方向

- 音频转写与无字幕视频支持。
- Gemini、Claude 等原生模型适配器。
- 飞书等知识平台同步。
- 本地任务历史和断点续传。
- Firefox、Edge、Safari 支持。
- 播放列表批量处理与模板化输出。

## 4. 用户流程

### 4.1 首次使用

1. 用户安装插件。
2. 用户打开设置，填写 API Key、Base URL 和模型名称。
3. 插件要求用户授权该 Base URL 的具体来源权限。
4. 用户点击“测试连接”。
5. 连接成功后，配置保存在 `chrome.storage.local`。

### 4.2 视频处理

1. 用户打开 YouTube 或哔哩哔哩视频页面。
2. 用户点击扩展图标，打开 Side Panel。
3. 插件识别当前视频、时长、平台和可用字幕轨道。
4. 用户选择字幕轨道、处理模式和是否保留时间戳。
5. 用户点击“开始生成”。
6. 插件展示字幕提取、清洗、分块、翻译或精炼的实时进度。
7. 完成后，用户预览、复制或下载 Markdown。

### 4.3 页面切换

- 当前任务进行时，如果活动标签页切换到另一个视频，Side Panel 显示确认提示。
- 用户可以继续当前任务，或取消当前任务并加载新视频。
- MVP 不自动把任务转移到新视频，也不静默取消任务。

## 5. 功能需求

### FR-1 平台识别

- 插件仅在受支持的 YouTube、哔哩哔哩视频页面启用完整功能。
- 对首页、搜索页、频道页、动态页等非视频页面显示“不支持当前页面”。
- 平台识别逻辑不得依赖页面显示语言。

### FR-2 视频元数据

- 读取平台、视频 ID、标题、作者、规范 URL 和时长。
- 缺少非必要字段时允许继续处理。
- 标题用于 Markdown 一级标题与默认文件名，必须移除文件系统非法字符。

### FR-3 字幕轨道

- 列出可访问的字幕语言、字幕名称和自动/人工字幕标识（平台提供时）。
- 字幕轨道默认由插件自动选择，不作为主流程设置展示。
- 自动选择优先使用与输出语言一致的人工字幕，其次为一致语言的自动字幕，再选择其他人工字幕和首个可用轨道。
- 用户可以在折叠的“字幕来源”高级设置中手动覆盖自动选择。
- 没有可访问字幕时返回 `NO_SUBTITLE`，不得降级为音频下载。
- 字幕接口返回合法结构但没有可提取正文时必须停止任务，不得生成空文档或调用模型补写内容。

### FR-4 字幕标准化

- 解码 HTML 实体与平台转义字符。
- 去除空字幕和完全重复字幕。
- 合并滚动字幕造成的前后重叠文本。
- 保留每条字幕的开始和结束时间。
- 根据标点、时间间隔和长度恢复自然段。
- 标准化阶段不主动删除语气词、事实或观点。

### FR-5 高保真模式

- 字幕语言与输出语言相同时不调用模型改写，只进行确定性的清洗与排版。
- 字幕语言与输出语言不同时按自然段分块翻译成用户选择的中文或英文。
- 每个输入段落携带稳定 ID，模型输出必须保留对应 ID。
- 插件校验输出段落覆盖率、唯一性和顺序。
- 校验失败时只重试失败分块。
- 最终 Markdown 只保留用户选择的输出语言，不生成双语正文。

### FR-6 AI 精炼模式

- 字幕按模型上下文窗口和安全余量分块。
- 第一阶段从每块提取章节候选、观点、事实、数字、人物、案例和结论。
- 第一阶段所有结构化条目必须引用当前分块内真实存在的来源段落 ID。
- 第二阶段合并各块结果，消除重复并恢复全局结构。
- 输出必须保留关键事实和论证关系，不得把未经字幕支持的内容写成事实。
- Map、Reduce、预览标题和 Markdown 章节标题均使用用户选择的输出语言。
- 对模型返回的结构执行校验；无法修复时保留可用结果并提示用户。

### FR-7 时间戳

- 用户可以开启或关闭时间戳。
- 时间戳链接使用平台支持的原视频定位格式。
- 高保真模式按自然段插入时间戳。
- AI 精炼模式仅在能追溯到来源字幕时插入时间戳，不伪造定位信息。

### FR-8 任务控制

- 显示当前阶段、完成分块数、总分块数、百分比和已用时间。
- 支持取消当前任务。
- 支持重试单个失败分块。
- 失败时保留已经成功的分块结果。
- 关闭 Side Panel 会中止当前任务，并明确提示该限制。

### FR-9 Markdown 输出

- 完成后在 Side Panel 内显示只读预览。
- 支持复制到系统剪贴板。
- 支持下载 UTF-8 编码的 `.md` 文件。
- 默认文件名格式为安全化后的视频标题。
- 模型输出只作为文本或经过验证的结构化数据处理，不执行 HTML。

### FR-10 模型配置

- 支持 API Key、Base URL 和模型名称。
- Base URL 默认只接受 HTTPS；开发构建可以允许 localhost。
- 提供连接测试、更新密钥和删除密钥功能。
- 模型适配层以 OpenAI 兼容协议为首个实现。

## 6. Markdown 规范

### 6.1 公共元信息

```md
# 视频标题

> 来源：YouTube / 哔哩哔哩
> 作者：作者名称
> 视频：原始视频 URL
> 处理模式：高保真 / AI 精炼
> 生成时间：ISO 8601 本地时间
```

缺少作者时省略作者行，不输出空占位符。

### 6.2 高保真模板

```md
## 根据内容生成或恢复的章节标题

[00:03:24](https://www.youtube.com/watch?v=VIDEO_ID&t=204s)

中文正文自然段。
```

如果用户关闭时间戳，则删除时间戳行，不改变正文结构。

### 6.3 AI 精炼模板

```md
## 内容概览

## 核心观点

## 章节笔记

### 章节名称

## 重要案例与数据

## 结论与启发
```

不存在案例或数据时允许省略对应章节，不输出虚构内容。

## 7. 统一数据模型

```ts
type Platform = 'youtube' | 'bilibili'

type VideoMetadata = {
  platform: Platform
  videoId: string
  title: string
  author?: string
  canonicalUrl: string
  durationMs?: number
}

type SubtitleTrack = {
  id: string
  language: string
  label: string
  isAutoGenerated?: boolean
}

type SubtitleCue = {
  id: string
  startMs: number
  endMs: number
  text: string
}

type VideoDocument = {
  metadata: VideoMetadata
  track: SubtitleTrack
  cues: SubtitleCue[]
}
```

内部数据模型不暴露平台私有响应结构。平台私有字段只存在于对应适配器内部。

## 8. 技术架构

### 8.1 技术栈

- WXT：扩展构建、多入口管理、开发与打包。
- React：Side Panel 与设置界面。
- TypeScript strict：业务代码、消息契约和数据模型。
- pnpm：依赖管理。
- Vitest：单元测试与契约测试。
- Testing Library：React 组件测试。
- Playwright：扩展集成与端到端测试。
- ESLint、Prettier：静态检查与格式化。

### 8.2 扩展组件

```text
YouTube / Bilibili 页面
        ↓
平台 Content Script + SubtitleAdapter
        ↓ 统一 VideoDocument
Side Panel 任务编排器
        ↓ 消息请求
Service Worker
        ↓ OpenAI 兼容 API
模型响应
        ↓
Processor 校验与合并
        ↓
Markdown Renderer
        ↓
预览 / 复制 / 下载
```

### 8.3 模块职责

#### Content Script

- 识别当前平台和视频页面。
- 读取当前页面上下文可访问的视频元数据与字幕信息。
- 调用平台适配器并返回统一数据。
- 不接收、不读取、不记录 API Key。

#### Side Panel

- 展示视频与字幕状态。
- 收集处理选项。
- 编排当前任务、管理取消信号和展示进度。
- 保存当前会话中的成功分块和错误状态。
- 关闭时取消未完成任务。

#### Service Worker

- 读取模型配置。
- 验证消息来源和请求结构。
- 向用户授权的模型来源发送请求。
- 映射网络、鉴权、限速和服务端错误。
- 返回模型文本或结构化响应，不向 Content Script 返回密钥。

#### Processor

- 清洗、去重、段落恢复和分块。
- 执行高保真翻译或分层精炼。
- 校验模型响应的 ID、结构、顺序和覆盖率。
- 合并成功结果并产生可重试的失败描述。

#### Markdown Renderer

- 从经过验证的领域对象生成 Markdown。
- 转义或规范可能破坏 Markdown 结构的内容。
- 生成平台时间戳 URL 和安全文件名。

### 8.4 核心接口

```ts
interface SubtitleAdapter {
  supports(url: URL): boolean
  getVideoMetadata(): Promise<VideoMetadata>
  getSubtitleTracks(): Promise<SubtitleTrack[]>
  getCues(track: SubtitleTrack): Promise<SubtitleCue[]>
}

interface ModelProvider {
  testConnection(): Promise<void>
  complete(request: ModelRequest): Promise<ModelResponse>
}
```

所有跨扩展上下文消息使用可区分联合类型，并在接收端执行运行时校验。不得信任来自 Content Script 的任意 URL、方法名或请求头。

## 9. 长视频处理策略

### 9.1 分块

- 以自然段为最小单元，不在句子中间硬切。
- 根据模型配置的上下文窗口、提示词占用和输出安全余量计算最大输入量。
- 无法确定模型上下文窗口时使用保守默认值。
- 相邻精炼分块保留有限重叠，以维持跨边界语义。
- 高保真翻译依赖稳定段落 ID，不通过重叠制造重复正文。

### 9.2 并发与退避

- 默认使用保守的小并发，避免瞬时触发限速。
- 遇到 429 或可重试的 5xx 错误时采用带抖动的指数退避。
- 尊重服务端提供的 `Retry-After`。
- 鉴权失败、无效模型、无效请求等错误不自动重复重试。

### 9.3 响应校验

- 高保真模式校验 ID 集合、唯一性和顺序。
- 精炼模式校验必需字段、字段类型和最大长度。
- 缺少部分输出时标记具体分块，不把任务误报为完整成功。
- Markdown 渲染器只接收通过校验的领域对象。

## 10. 权限与安全

### 10.1 Manifest 权限

- `sidePanel`：显示 Side Panel。
- `storage`：保存本地配置和偏好。
- `downloads`：导出 Markdown。
- YouTube、哔哩哔哩的限定页面来源权限。
- 模型 API 使用可选来源权限；配置 Base URL 后请求具体来源授权。

不申请 Cookie、浏览历史、麦克风、摄像头或不必要的全站永久访问权限。

### 10.2 密钥处理

- API Key 只写入 `chrome.storage.local`，不写入同步存储。
- API Key 只由设置页和 Service Worker 访问。
- UI 默认遮挡密钥，不提供明文日志。
- 所有错误对象和日志在输出前执行凭证脱敏。
- 删除密钥后立即使模型功能不可用，直到重新配置。
- 文档明确说明浏览器本地存储不是硬件级安全存储，不承诺绝对安全。

### 10.3 内容安全

- 不使用 `eval` 或动态远程代码。
- 不把模型返回内容作为 HTML 注入页面。
- Content Script 消息视为不可信输入，必须进行类型与来源校验。
- Service Worker 只允许访问用户已授权的模型来源，拒绝由页面传入的任意目标 URL。
- 原始字幕和生成结果不发送到产品自有服务器。

## 11. 错误模型

```ts
type ErrorCode =
  | 'UNSUPPORTED_PAGE'
  | 'NO_SUBTITLE'
  | 'SUBTITLE_EXTRACTION_FAILED'
  | 'INVALID_MODEL_CONFIG'
  | 'MODEL_AUTH_FAILED'
  | 'MODEL_RATE_LIMITED'
  | 'MODEL_CONTEXT_EXCEEDED'
  | 'MODEL_RESPONSE_INVALID'
  | 'NETWORK_FAILED'
  | 'TASK_CANCELLED'
```

### 11.1 恢复规则

- `UNSUPPORTED_PAGE`：引导用户打开受支持的视频页面。
- `NO_SUBTITLE`：说明 MVP 只处理已有字幕的视频。
- `SUBTITLE_EXTRACTION_FAILED`：允许重试，并提示可能是平台页面发生变化。
- `INVALID_MODEL_CONFIG`：跳转到设置并保留非敏感表单内容。
- `MODEL_AUTH_FAILED`：停止自动重试，提示检查密钥和 Base URL。
- `MODEL_RATE_LIMITED`：展示等待状态，并允许取消。
- `MODEL_CONTEXT_EXCEEDED`：降低单块大小后只重试失败分块。
- `MODEL_RESPONSE_INVALID`：执行一次受控修复或重试，仍失败则保留其他结果。
- `NETWORK_FAILED`：提示网络状态并允许重试。
- `TASK_CANCELLED`：保留已完成分块到当前 Side Panel 会话。

错误文案必须描述发生了什么、哪些结果仍然可用，以及用户下一步可以做什么。

## 12. 界面状态

### 12.1 未配置

- 显示模型配置入口。
- 核心生成按钮禁用。
- 用户可以先查看已识别的视频和字幕信息。

### 12.2 准备

- 显示平台、字幕语言、视频时长和标题。
- 提供模式、字幕轨道和时间戳选项。
- 解释所选模式会如何处理内容。

### 12.3 处理中

- 显示阶段、分块进度、百分比和已用时间。
- 显示取消按钮。
- 已成功结果不因单块失败而丢失。

### 12.4 部分完成

- 明确标识失败分块数量。
- 提供“重试失败部分”。
- 在用户明确选择时允许导出部分结果，并在文档中标注不完整。

### 12.5 完成

- 显示文档标题、字数、时间戳数量和 Markdown 预览。
- 提供下载、复制和重新生成。

## 13. 性能与隐私要求

- 字幕清洗和分块不得阻塞 Side Panel 的交互反馈。
- 30 分钟字幕在常见开发设备上应能顺畅完成本地预处理。
- 模型调用期间持续显示可感知的进度，而不是无限加载状态。
- 不使用分析追踪 SDK 作为 MVP 的默认依赖。
- 不收集浏览历史、视频观看历史、字幕内容或模型凭证。
- 隐私说明必须列出发送给模型提供商的数据范围，并说明该行为受用户所选提供商条款约束。

## 14. 测试策略

### 14.1 单元测试

- 字幕实体解码与空白规范化。
- 完全重复与滚动字幕重叠去重。
- 自然段恢复。
- 高保真段落 ID 生成与覆盖率校验。
- 上下文预算与分块边界。
- 退避与错误映射。
- 时间戳 URL 和安全文件名。
- Markdown 模板渲染。

### 14.2 固定样本测试

## 20. Side Panel 2.0 交互升级概述

### 20.1 背景

0.1.0 已经具备视频识别、字幕选择、模型配置、任务处理和 Markdown 导出能力，但当前界面主要按程序内部状态组织，用户需要自行理解“先配置模型、再刷新页面、再选择字幕、再开始生成”的顺序。模型请求期间只能看到粗粒度分块进度，单次请求尚未返回时缺少持续反馈，容易被理解为卡死。

0.2.0 的目标不是单纯调整视觉样式，而是把产品重构为明确的三段式任务：

```text
识别当前视频 → 配置生成方式 → 可视化生成与导出
```

### 20.2 升级目标

- 用户打开插件后 5 秒内能够理解当前状态和下一步操作。
- 当前视频、字幕和模型状态在开始生成前可被一次性确认。
- 仅在所选任务确实需要模型时要求配置 API。
- 插件刚安装或更新导致页面脚本未加载时，提供原因明确的一键刷新操作。
- 模型等待超过 2 秒后始终提供持续、可信的状态反馈。
- 每个已校验分块完成后立即展示新增内容，不等待整个任务结束。
- 支持模型 Token 流式传输时逐步显示可读内容，不展示不完整 JSON。
- 一个页面只保留一个最高权重的主操作，其他操作按次级、文字或危险层级展示。
- 结果默认以阅读视图展示，并允许切换到 Markdown 源码。

### 20.3 非目标

- 本期不新增产品账号、云端任务历史或跨设备同步。
- 本期不承诺关闭 Side Panel 后继续执行任务。
- 本期不为无字幕视频增加音频转写。
- 本期不增加飞书、Notion、Obsidian 等平台同步。
- 本期不以展示模型思维过程或内部 Map 数据作为“流式输出”。

## 21. 产品原则与任务模型

### 21.1 产品原则

1. 先展示上下文，再要求配置：用户应先看到当前视频和字幕状态，再决定生成方式。
2. 按需配置模型：本地可以完成的任务不因缺少 API Key 被阻断。
3. 状态必须可解释：加载、等待、重试、失败都应说明正在发生什么以及用户可以做什么。
4. 增量结果优先：已验证的内容立即可见，后续失败不得清空已有结果。
5. 结果可读优先：默认提供阅读预览，Markdown 源码作为辅助视图。
6. 渐进披露：时间戳、上下文窗口等低频设置不占据主流程的视觉中心。
7. 安全降级：模型不支持流式时自动降级到分块增量输出，不影响最终结果正确性。

### 21.2 模型依赖矩阵

| 字幕与模式 | 是否需要模型 | 无模型时的产品行为 |
| --- | --- | --- |
| 中文字幕 + 高保真 | 否 | 允许直接生成，执行本地清洗、断句和排版 |
| 非中文字幕 + 高保真中文 | 是 | 主按钮切换为“配置模型并继续” |
| 任意字幕 + AI 精炼 | 是 | 主按钮切换为“配置模型并继续” |

### 21.3 主任务状态

```ts
type ProductPhase =
  | 'booting'
  | 'unsupported-page'
  | 'refresh-required'
  | 'video-ready'
  | 'configuration-required'
  | 'generating'
  | 'partial'
  | 'completed'
  | 'failed'
  | 'cancelled'
```

产品状态与技术错误码分离。技术错误用于诊断，产品状态用于决定用户看到的页面和可执行操作。

## 22. 信息架构与全局布局

### 22.1 Side Panel 全局结构

Side Panel 使用从上到下的固定信息层级：

1. 顶部栏：产品标识、任务状态入口、设置入口。
2. 当前视频区：平台、标题、作者、时长、字幕识别状态。
3. 当前任务区：准备选项、生成进度、部分结果或最终结果。
4. 底部操作栏：当前页面唯一主操作和必要次级操作。

顶部栏和底部操作栏可以固定，中间内容区独立滚动。不得因为内容较少在底部产生大面积无意义空白，也不得让主要按钮随长内容滚出视口。

### 22.2 视觉层级

- 页面背景使用中性浅灰，主要内容使用白色卡片。
- 主色用于当前选择、进度和唯一主按钮。
- 每个页面最多一个实心高强调按钮。
- 次操作使用描边、浅色背景或文字按钮。
- 危险操作只用于删除配置、停止并丢弃等不可逆动作。
- 设置入口使用图标按钮，不使用与主任务竞争的大面积实心按钮。
- 正文使用系统无衬线字体；只有 Markdown 源码使用等宽字体。
- 推荐 8px 间距体系、8 至 12px 卡片圆角、40 至 44px 主按钮高度。

### 22.3 响应式要求

- 重点覆盖 320px 至 600px 宽的 Chrome Side Panel。
- 设计基准画板宽度为 380px，高度为 760px。
- 320px 宽度下不得出现横向滚动、文字遮挡或三个按钮并排拥挤。
- 600px 宽度下内容最大阅读宽度不超过 520px，并保持居中或合理留白。

## 23. 页面与状态需求

### 23.1 首次打开与不支持页面

当当前标签页不是受支持的视频页时，页面展示：

- 简短价值说明：“把 YouTube 和 B 站字幕整理为中文 Markdown”。
- 支持平台标签。
- 三步说明：打开视频、选择生成方式、生成并导出。
- 主操作：“重新检测当前页面”。
- 次级帮助：“如何使用”。

不得在没有视频上下文时直接展示完整 API 表单。

### 23.2 需要刷新页面

以下场景进入 `refresh-required`：

- 插件刚安装或更新，已有视频页未注入当前版本内容脚本。
- 内容脚本多次握手失败，但标签页 URL 属于受支持页面。

页面必须说明原因，而不是笼统显示“字幕读取失败”：

> 插件刚刚安装或更新，需要刷新当前视频页面后才能读取字幕。

主操作为“刷新当前视频页”。点击后由插件发起刷新、展示加载状态并自动重新检测。保留“稍后再试”作为低权重操作。

### 23.3 视频准备页

视频准备页包含：

- 视频卡片：平台标识、标题、作者、时长。
- 字幕状态：已识别数量、当前选择、人工或自动生成标识。
- 模式选择卡片：高保真中文稿、AI 精炼笔记。
- 字幕轨道选择器。
- 模型状态行：无需模型、已连接、未配置或连接异常。
- 折叠的“更多选项”：时间戳等低频设置。
- 动态主按钮。

模式文案：

- 高保真中文稿：尽可能保留完整内容、细节、表达顺序和论证过程；非中文自动翻译为中文。
- AI 精炼笔记：整理为内容概览、核心观点、章节笔记、重要事实和结论。

动态主按钮规则：

- 可直接执行：“生成高保真中文稿”或“生成 AI 精炼笔记”。
- 缺少模型：“配置模型并继续”。
- 没有字幕：禁用并显示“当前视频没有可用字幕”。
- 正在检测：禁用并显示“正在读取字幕…”。

### 23.4 模型设置

模型设置使用独立页面或覆盖式抽屉，关闭后回到之前的任务上下文。设置内容包括：

- 服务商预设：DeepSeek、OpenAI、OpenRouter、自定义。
- API Key，默认遮挡，允许临时显示。
- Base URL，预设自动填充，自定义时允许编辑。
- 模型名称。
- 当前连接状态和最近一次测试结果。
- 数据将发送至用户所选模型服务商的隐私提示。

主操作为“保存并测试”，次操作为“仅保存”。删除配置放在页面底部的危险操作区，不与保存操作并排。

测试期间至少展示目标域名、已等待时间和取消能力。成功后展示响应耗时；失败后展示可执行建议，不得只显示错误代码。

### 23.5 生成中

生成页分为任务摘要、阶段进度和实时内容三部分。

任务摘要显示视频标题、生成模式和已用时间。阶段进度至少包括：

1. 读取字幕。
2. 清洗与恢复段落。
3. 翻译或提炼分块。
4. 汇总和生成 Markdown。

实时内容区要求：

- 有已验证内容时立即追加到阅读预览。
- 没有可展示内容时显示当前请求状态、已等待时间和活动指示器。
- 默认自动滚动到最新内容。
- 用户主动向上滚动后暂停自动滚动，并显示“回到最新”。
- 显示已生成字数、完成分块数和总分块数。
- 当前内容末尾可显示非侵入式生成光标，但不得模拟不存在的模型输出。

底部主操作为“停止生成”，必须区分“停止并保留已完成内容”和未来可能提供的“停止并丢弃”。MVP 默认保留已完成内容。

### 23.6 部分完成

存在失败分块时展示：

- 已成功与失败的分块数量。
- 已生成内容预览。
- 每个失败分块的简化原因和重试状态。
- 主操作“重试失败部分”。
- 次操作“导出当前结果”，导出文件必须标注内容不完整。
- 文字操作“返回并调整设置”。

重试不得重复请求已经成功的分块，也不得打乱原始内容顺序。

### 23.7 完成结果

完成页默认展示阅读预览，并提供“阅读预览 / Markdown 源码”切换。

结果摘要至少包含：

- 完成状态。
- 处理模式。
- 分块数量。
- 字数。
- 总耗时。

底部操作层级：

1. 主操作：“复制 Markdown”。
2. 次操作：“下载 .md”。
3. 低权重操作：“重新生成”，放入更多菜单或页面顶部。

复制成功后使用短暂状态反馈，不弹出阻断式对话框。Markdown 源码区允许选择文本，但不得直接编辑最终领域对象。

### 23.8 取消与失败

- 取消后保留本会话中已经验证的分块。
- 有可用内容时优先进入部分完成页，而不是空白取消页。
- 没有可用内容时说明任务停止在哪个阶段。
- 鉴权失败提供“检查模型设置”。
- 限速错误展示自动重试倒计时和“立即取消”。
- 网络中断允许重试当前分块。
- 字幕提取失败区分“需要刷新”“没有字幕”和“平台响应异常”。

## 24. 增量输出与流式协议需求

### 24.1 两级流式能力

0.2.0 将实时输出拆成两个可独立交付的层级：

#### Level 1：分块增量输出

- 每个分块在模型完整返回、结构校验通过后立即写入实时预览。
- 高保真模式按原始分块和段落顺序追加正文。
- 中文字幕高保真模式在本地处理后立即展示，不制造模型等待状态。
- AI 精炼 Map 阶段只展示“正在理解第 N / M 部分”等任务进度，不展示内部结构化中间结果。
- 已完成分块存入当前任务会话，后续失败不清空。

Level 1 是 0.2.0 的必须能力，不依赖模型是否支持 SSE。

#### Level 2：Token 流式传输

- 对支持 OpenAI 兼容流式协议的提供商发送 `stream: true`。
- Service Worker 解析 SSE，并通过长连接向 Side Panel 推送增量事件。
- 服务明确不支持流式，或在尚未接收可验证内容前返回普通 JSON 时，自动降级到 Level 1。
- 流式连接在接收过程中中断时丢弃未验证增量并重试当前分块，不把残缺内容写入文档。
- 降级和重试行为对用户透明，但允许在诊断信息中查看。

### 24.2 结构化内容的可读流式约束

当前模型响应使用完整 JSON 校验。直接展示 JSON Token 会出现字段名、花括号和不完整字符串，禁止把这类内容作为用户正文展示。

推荐协议：

- 高保真翻译使用 NDJSON；每行是一个独立、可验证的段落对象。
- 只有完整行解析成功、ID 合法且顺序可确定后才追加到预览。
- AI 精炼 Reduce 阶段按语义单元输出 NDJSON，例如 `overview`、`core_idea`、`chapter`、`fact`、`conclusion`。
- 无法使用 NDJSON 的模型保留完整 JSON 响应，并按 Level 1 展示。

### 24.3 任务事件模型

```ts
type TaskEvent =
  | { type: 'TASK_STARTED'; taskId: string; startedAt: number }
  | { type: 'SUBTITLE_LOADED'; cueCount: number; language: string }
  | { type: 'PARAGRAPHS_READY'; paragraphCount: number; chunkCount: number }
  | { type: 'CHUNK_STARTED'; chunkIndex: number; totalChunks: number }
  | { type: 'MODEL_CONNECTED'; chunkIndex: number }
  | { type: 'STREAM_ACTIVITY'; receivedChars: number }
  | { type: 'CONTENT_APPENDED'; chunkId: string; content: unknown }
  | { type: 'CHUNK_RETRYING'; chunkId: string; attempt: number; retryAt: number }
  | { type: 'CHUNK_COMPLETED'; chunkId: string }
  | { type: 'REDUCE_STARTED'; totalInputs: number }
  | { type: 'TASK_COMPLETED'; document: ProcessedDocument }
  | { type: 'TASK_PARTIAL'; failedChunkIds: string[] }
  | { type: 'TASK_FAILED'; error: PublicAppError }
  | { type: 'TASK_CANCELLED'; preservedChunkIds: string[] }
```

UI 只订阅任务事件，不直接推断底层 Fetch 状态。事件必须带任务 ID，避免旧任务响应污染新任务。

### 24.4 长连接与取消

- 单次请求-响应消息继续用于配置测试等短操作。
- 模型生成任务使用 `chrome.runtime.connect()` 或等效长连接。
- Side Panel 关闭、用户取消或任务替换时，必须中止对应 Fetch。
- 端口断开后 Service Worker 终止当前请求，除非未来版本明确支持后台续跑。
- 取消后不再接受该任务的增量事件。

### 24.5 等待反馈

- 请求发出 0 至 2 秒：使用轻量活动指示器。
- 超过 2 秒没有内容：显示“正在等待模型响应”和已等待时间。
- 已收到流但尚无可验证内容：显示已接收字符数，不展示原始 JSON。
- 超过配置超时时间：显示可恢复错误并保留其他分块。
- 自动重试时显示原因、当前尝试次数和下一次重试倒计时。

## 25. 页面刷新与上下文同步

### 25.1 自动检测

- Side Panel 打开时读取当前活动标签页。
- 支持用户在已打开的 Side Panel 中切换标签页或切换到另一个视频。
- 页面脚本缓存和 Side Panel 握手必须同时校验视频 ID，SPA 导航期间不得返回上一个视频的上下文。
- 当前没有任务时自动加载新视频上下文。
- 当前存在任务时不得静默切换，提示用户继续当前任务或停止并加载新视频。

### 25.2 一键刷新

- 只有确认内容脚本未加载或版本不匹配时才显示刷新提示。
- 点击“刷新当前视频页”后进入明确的刷新中状态。
- 页面加载完成后自动重新握手，不要求用户再次点击检测。
- 刷新失败时提供手动刷新说明和重新检测入口。

### 25.3 上下文摘要

所有准备、设置、生成和结果页面尽量保留当前视频标题的简化上下文，防止用户在设置页中失去任务目标。

## 26. 模型设置与提供商适配

### 26.1 提供商预设

预设只提供常见默认值，不在客户端硬编码密钥。预设至少包含：

- DeepSeek。
- OpenAI。
- OpenRouter。
- 自定义 OpenAI 兼容服务。

每个预设定义 Base URL 示例、模型名称示例以及是否默认支持流式。用户仍可修改模型名称。

### 26.2 保存和测试

- “保存并测试”先保存并请求来源权限，再执行最长 15 秒的最小请求。
- 测试失败时保留输入，不自动关闭设置页。
- 测试成功后展示成功状态，由用户返回或自动在短暂停留后返回准备页。
- “仅保存”必须明确说明尚未验证连接。
- Base URL 规范化不得重复追加 `/v1` 或 `/chat/completions`。

### 26.3 隐私提示

设置页必须说明：

- API Key 保存在浏览器本地。
- 生成时字幕会发送给用户选择的模型服务商。
- 本插件不通过自有服务器转发内容。

## 27. 可访问性与交互细节

- 所有图标按钮具有可访问名称和提示。
- 键盘可以完成模式选择、字幕选择、设置保存、生成、取消和导出。
- 焦点状态清晰可见，不只依赖颜色表达状态。
- 文字与背景对比度至少达到 WCAG AA。
- 进度变化通过 `aria-live="polite"` 提供非干扰通知。
- 错误使用 `role="alert"`，普通成功反馈使用 `role="status"`。
- 动画遵循 `prefers-reduced-motion`。
- 自动滚动只在用户未主动离开底部时进行。

## 29. Side Panel 2.0 验收标准

1. 用户打开插件后 5 秒内可以识别当前视频状态和下一步操作。
2. 不支持页面不直接展示完整模型配置表单。
3. 中文字幕高保真在无 API 配置时仍可开始。
4. 非中文字幕高保真和 AI 精炼在无配置时进入“配置模型并继续”。
5. 内容脚本未加载时显示一键刷新，而不是统一归类为字幕错误。
6. 准备页只有一个最高权重主按钮。
7. 模型测试显示目标域名、已等待时间和明确结果。
8. 模型等待超过 2 秒时持续提供可信状态反馈。
9. 每个已验证分块完成后立即出现在实时预览中。
10. 用户向上阅读时不会被自动滚动强制拉回底部。
11. 单块失败不会删除其他成功结果，并允许只重试失败分块。
12. 流式不可用时自动降级，不影响最终结果正确性。
13. 完成页默认展示阅读预览，并可切换 Markdown 源码。
14. 复制、下载和重新生成具有明确的主次层级。
15. 320px 宽度下无横向滚动、文字遮挡和按钮拥挤。
16. 任务、设置和错误状态满足键盘操作与基础可访问性要求。
