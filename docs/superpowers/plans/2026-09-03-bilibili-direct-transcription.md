# B 站无字幕视频直接转录实施计划（P2B）

## 1. 目标

当 B 站当前分集没有平台字幕轨、没有可访问的发布者文稿时，用户无需寻找或访问 YouTube 原视频，即可从当前标签页音频生成带时间戳的文字，并继续使用现有的高保真或 AI 精炼 Markdown 流程。

## 2. 产品原则

- 只处理用户明确点击“转录当前视频”的当前标签页，不后台自动录音。
- 第一阶段以音频 ASR 为主，解决所有有声音但无字幕轨的视频。
- 第二阶段增加画面 OCR，用于读取烧录字幕和校正 ASR 专有名词。
- 不调用 B 站非公开下载接口，不猜测其他视频，不依赖 YouTube 可访问性。
- 音频上传、服务商、模型、费用和隐私范围必须在开始前明确展示。
- 停止任务时保留已经完成的转录分段。

## 3. P2B-1：当前标签页音频转录

### 3.1 配置

新增独立的“转录模型”配置，不与文本生成模型混用：

- 转录接口 URL
- API Key
- 模型名称
- 输入语言：自动、中文、英文
- 单块录制时长：默认 30 秒

接口采用 OpenAI 兼容的 `multipart/form-data` `/audio/transcriptions` 协议，返回带分段时间戳的 verbose JSON；服务商不支持 verbose JSON 时兼容纯文本响应。

### 3.2 标签页捕获

- Manifest 增加 `tabCapture` 与 `offscreen` 权限，最低 Chrome 版本提升为 116。
- 用户点击后由 Service Worker 获取当前标签页 `MediaStreamId`。
- Offscreen Document 消费音频流，保持原视频声音继续播放。
- 录制器每 30 秒停止并重新启动，形成可独立上传的 WebM 音频块。
- 只捕获音频，不录制或上传画面。

### 3.3 转录任务

- 每个音频块按顺序上传，避免服务商限流。
- 将服务商返回的相对时间戳加上当前块起始时间。
- 通过消息事件持续回传：捕获中、上传中、已完成块数、实时文字、错误。
- 用户停止时结束录制并处理最后一个非空音频块。
- 页面切换、标签页关闭、媒体流结束时安全停止。

### 3.4 接入现有 Markdown

- 将 ASR 分段映射为现有 `SubtitleCue[]`。
- 注册为当前 B 站视频的临时字幕轨 `asr:<bvid>:<taskId>`。
- 转录完成后进入现有“生成设置”，用户继续选择中文/英文、高保真/AI 精炼。
- ASR 轨保留真实时间戳并接受现有完整性校验。

## 4. P2B-2：烧录字幕 OCR

- 通过同一个 `tabCapture` 流采集视频帧。
- 默认每秒 1～2 帧，仅裁剪播放器底部字幕区域。
- 使用浏览器 OCR 模型识别中英文字幕。
- 按图像哈希、文本相似度和时间窗口去重。
- OCR 结果与 ASR 按时间轴对齐，用于专有名词、数字和翻译校正。
- 没有检测到稳定字幕区域时自动退回纯 ASR，不阻断任务。

OCR 不进入 P2B-1 首次交付，避免把模型体积、WebGPU 兼容和字幕区域检测风险带入基础转录闭环。

## 5. UI 状态

无字幕页面新增主操作：

1. `直接转录当前视频（推荐）`
2. 展示“将从头播放并捕获当前标签页音频”的确认说明
3. 未配置时展开转录模型设置
4. 转录中显示：已录制时长、已转录时长、当前分段、实时文字
5. 支持 `停止并保留已完成内容`
6. 完成后进入现有生成设置

发布者文稿和 YouTube 原链接调整为次级恢复方式。

## 6. 验收标准

- 没有字幕轨的 B 站视频可以从当前标签页直接开始转录。
- 未经用户点击不会请求捕获权限、播放视频或上传音频。
- 视频音频在捕获期间仍可正常播放。
- 30 秒音频块可以独立转录并产生单调递增时间戳。
- 停止、页面切换和网络错误不会丢失已完成分段。
- 转录结果可进入现有 Markdown 高保真和 AI 精炼流程。
- 单元、集成、E2E、类型检查、Lint 和生产构建通过。

## 7. 执行顺序

1. 配置模型与接口抽象
2. Offscreen 音频录制
3. Service Worker 任务协调
4. 无字幕页面转录交互
5. 转录结果注册与 Markdown 接入
6. 自动化测试
7. 当前 B 站视频真实验收
8. P2B-2 OCR 混合校验

## 8. 2026-09-19 续作记录

- P2B-1 已有代码闭环：独立语音模型配置、标签页录音、分段转写、停止保留内容与 Markdown 接入。
- 修复响应正文读取不受超时保护的问题，补充正文挂起回归测试。
- 转录任务改为由发起端预分配标识；页面只接收当前任务事件，忽略旧任务的延迟消息和启动响应，避免切换视频后结果串入。
- 49 个测试文件、392 项单元／集成测试通过；类型检查、Lint、生产构建通过。
- 真实浏览器连接超时，当前视频的实际录音、接口上传、停止恢复仍待人工或恢复连接后验收。自动化界面测试使用模拟转录事件，不能替代真实音频验收。
- OCR 属于 P2B-2，尚未实现；当前直接提取能力基于音频转写，不应宣称可识别画面内的烧录字幕。

## 9. 2026-09-20 火山方舟适配

- 新增可选 `ark-responses` 协议；未设置协议的旧配置保持原音频上传协议。
- 使用 `input_audio.audio_url` 内嵌本地转换的单声道 PCM16 WAV，请求关闭响应存储。
- 提示模型只转写原语言；严格解析完成状态及 JSON 文字结果，拒绝截断、缺失或错误格式。时间戳使用录音分段边界，不声称逐词精度。
- 设置页提供方舟接口与模型默认值，切换服务清空密钥；不把用户密钥写入源码、测试或文档。
- 验收分两层：自动化验证请求、转换和解析；用户填写新密钥后再执行真实 30～60 秒音频验收。本次不复用聊天中已暴露的密钥。
- 前轮真实页面测试出现错误字幕来源，仍属独立待修复项；不能将本次接口适配等同于解决字幕来源错误。
