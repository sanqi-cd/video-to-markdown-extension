# 标签页音频采集启动修复与验收

## 问题与边界

实测失败发生在获取标签页音频流标识阶段，尚未到达语音模型。旧提示将所有异常归为页面未打开，无法指导用户恢复。补充 activeTab 并不等于永久授予所有标签页录音权限：用户仍需在目标视频页主动点击扩展图标。

## 本次变更

- 声明 activeTab；在转录入口说明当前标签页的授权操作。
- 校验目标页仍处于激活状态，检查已有采集，并串行化启动，防止重复启动。
- 将未授权、已有采集、标签页失效分别映射为安全的中文提示，不向界面输出原始错误、地址或密钥。
- 后台采集器启动失败及播放准备失败时尝试停止采集、恢复播放；启动锁始终释放。
- 录音初始化异常释放已取得的媒体流；停止录制后不等模型响应才释放采集资源。

## 自动验收

新增启动控制器回归测试：授权提示和脱敏、失败后重试、非当前页拦截、重复启动、播放准备失败清理、后台初始化失败清理。

## 真实浏览器验收（须重新加载构建产物）

1. 重新加载 `.output/chrome-mv3` 对应扩展。如 Chrome 提示新权限，由用户确认。
2. 回到 B 站视频页，点击工具栏或扩展菜单中的 Video to Markdown 图标，再启动转录。
3. 首轮仅录制约 30 秒后停止，检查音频上传、文本返回与停止后的播放恢复。可能发生模型调用费用，不用整段长视频验证。
4. 切换新标签页后检查授权提示；不要把“重新检测字幕”描述为音频授权。
5. 重复点击不得产生两个任务；失败后再次开始不得被本插件残留采集阻塞。

自动测试不证明浏览器授权或模型真实音频能力已通过。真实结果需单独记录。
