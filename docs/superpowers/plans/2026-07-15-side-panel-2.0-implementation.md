- 计划日期：2026-07-15

## 1. 目标

将当前以程序状态为中心的 Side Panel 升级为以用户任务为中心的完整流程：

```text
识别当前视频 → 配置生成方式 → 可视化生成与导出
```

0.2.0 必须实现：

- 模型按需配置，中文字幕高保真不被 API 配置阻断。
- 明确区分不支持页面、需要刷新、正在检测、无字幕和平台错误。
- 每个已验证分块完成后立即出现在实时预览中。
- 模型请求期间持续显示连接、等待、接收、重试和耗时信息。
- 支持 OpenAI 兼容 SSE 时提供 Token 流活动；不支持时安全降级。
- 部分失败保留成功内容并只重试失败分块。
- 结果默认展示阅读预览，可切换 Markdown 源码。
- UI 对齐 P01–P12，并满足 320px Side Panel 和基础可访问性要求。

## 2. 不在本计划范围内

- 关闭 Side Panel 后继续后台生成。
- 云端任务历史、账号和跨设备同步。
- 无字幕视频的语音识别。
- 飞书、Notion、Obsidian 等平台同步。
- Gemini、Claude 原生 API 协议。
- 多视频批处理和播放列表处理。

## 3. 当前实现与目标实现的差距

| 模块 | 当前实现 | 0.2.0 目标 |
| --- | --- | --- |
| 顶层状态 | `AppPhase` 直接决定页面 | 产品上下文、页面路由和任务状态分离 |
| 模型依赖 | 没有配置就不读取视频 | 根据字幕语言和模式动态判断 |
| 页面检测 | 失败统一进入 `context_error` | 区分加载、刷新、无字幕和平台异常 |
| 任务进度 | 阶段字符串和分块计数 | 稳定事件、指标、流活动和增量预览 |
| 模型通信 | `sendMessage()` 单次响应 | 短请求保留消息，长任务使用 Port |
| 模型响应 | 完整 JSON 后解析 | SSE 活动 + 可读结构化增量 + 完整降级 |
| 结果展示 | `<pre>` 原始 Markdown | 阅读预览和 Markdown 源码双视图 |
| 部分结果 | 只显示失败数量 | 展示成功内容、失败详情和部分导出 |
| 样式 | 单文件基础样式 | 设计变量、固定操作栏、响应式和状态组件 |

## 4. 架构决策

### 4.1 状态分层

顶层状态拆成三层，避免一个联合类型同时承担所有职责：

1. `VideoContextState`：活动标签页、平台、视频、字幕、刷新状态。
2. `AppRoute`：主页面、模型设置、模型测试、生成结果等界面导航。
3. `TaskSnapshot`：任务阶段、指标、增量内容、失败分块和最终文档。

界面不直接根据异常字符串猜测状态，错误码先经过产品状态映射函数。

### 4.2 两级实时输出

#### Level 1：分块增量

- 当前串行分块处理保留。
- 每个分块完整返回并通过结构校验后，立即发出 `CONTENT_APPENDED`。
- Level 1 不依赖 SSE，是 0.2.0 的发布门槛。

#### Level 2：Token 流式

- Service Worker 使用 `stream: true` 请求 OpenAI 兼容服务。
- SSE 数据经解析后通过 `chrome.runtime.Port` 传给 Side Panel。
- 原始 JSON Token 不作为正文展示，只作为接收活动和解析缓冲。
- 可读 NDJSON 单元校验通过后才转为 `CONTENT_APPENDED`。
- 提供商不支持流式时，在收到首个 Delta 前自动降级为非流式请求。
- 流式中途断开时丢弃尚未验证的缓冲，由现有分块重试策略处理。

### 4.3 结果渲染安全

- 阅读预览直接渲染 `ProcessedDocument` 领域对象。
- Markdown 源码继续由 `renderMarkdown()` 生成。
- 禁止使用 `dangerouslySetInnerHTML` 渲染模型内容。
- 生成时间在任务完成时固定，复制和下载不得重新计算。

### 4.4 兼容与迁移

- 现有 `modelConfig` 必须无损迁移，不要求用户重新填写 API Key。
- 现有 `userPreferences` 缺少新字段时使用默认值。
- 现有非流式模型调用保留为兼容路径和测试连接路径。
- YouTube Innertube/XML 字幕修复及 B 站字幕适配不得回退。

## 5. 任务依赖顺序

```text
任务 0 基线与设计收口
  ↓
任务 1 UI 基础与产品状态
  ↓
任务 2 视频上下文、刷新与标签页同步
  ↓
任务 3 模型按需配置与设置流程
  ↓
任务 4 任务事件与 Level 1 分块增量
  ↓
任务 5 生成页、自动滚动与部分结果
  ↓
任务 6 Port + SSE 流式传输
  ↓
任务 7 可读结构化流与降级
  ↓
任务 8 结果预览、源码与导出
  ↓
任务 9 响应式、可访问性与端到端测试
  ↓
任务 10 文档、打包与发布验收
```

任务 4 完成后即可获得明显改善的 Level 1 版本。任务 6–7 不得阻塞任务 1–5 的独立验收。

## 6. 全局质量规则

- 每项任务先补失败测试，再实现最小改动。
- 每项任务结束至少执行相关测试、`pnpm typecheck` 和 `pnpm lint`。
- 跨 Service Worker、Side Panel 的消息必须由 Zod 校验。
- 所有任务事件必须带 `taskId`，旧任务事件不得污染新任务。
- API Key 不得进入 Port 消息、Content Script、日志和测试快照。
- 所有新增错误文案说明发生了什么、已保留什么以及下一步操作。
- 不在 UI 重构提交中修改平台字幕解析算法。
- 不在流式协议提交中同时大规模调整视觉样式。

## 9. 风险与回滚策略

### 风险 1：不同提供商 SSE 格式差异

- 控制：只解析 OpenAI 兼容 `data:` 事件，严格校验 Chunk。
- 回滚：关闭 `streamMode`，保留非流式 `complete()`。

### 风险 2：NDJSON 遵循率不稳定

- 控制：完整缓冲，尝试 NDJSON 后再尝试完整 JSON。
- 回滚：只保留 Level 1 分块增量，不影响发布主流程。

### 风险 3：UI 重构导致字幕修复回退

- 控制：适配器测试不随 UI 改动删除；E2E 保留 XML 字幕样本。
- 回滚：UI 与字幕适配提交分离，可以独立回退。

### 风险 4：Service Worker 生命周期导致 Port 中断

- 控制：使用长连接维持任务会话，端口断开立即取消请求。
- 回滚：退回单次消息和 Level 1 非流式处理。

### 风险 5：旧配置无法读取

- 控制：先读 V2，再迁移 V1；迁移测试使用真实旧结构样本。
- 回滚：保留 V1 读取器一个版本周期。
